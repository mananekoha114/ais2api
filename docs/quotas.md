# 订阅等级与每日额度

AI Studio Playground 的每日额度按账号的 Google AI 订阅等级区分。ais2api 记录每个账号的等级，按一张额度表决定哪些账号可以使用某个模型、换号时先用哪个账号，并在本地估算每个账号当天的用量。额度表随程序内置一份快照，运行时从本项目仓库自动更新，额度调整或新模型上线时只需修改仓库里的数据文件，不用发新版本。

额度表中的数值是社区观测值，Google 可能随时调整，所以只用于选号排序和冷却时长，不会仅凭本地估算拒绝请求。

## 订阅等级

页面通过 `GetAiStudioBenefitTier` 确认账号的等级（见 [浏览器网关](browser.md#请求签名与会员等级)）。等级分为 `free`、`plus`、`pro`、`ultra` 四种：

- 探测账号以及每次生成尝试结束后，都会把页面确认的等级按账号保存；查询失败或结果未知时保留原有等级，不会清空。重置账号也不会清除等级。
- 账号升级或降级订阅后，本地的等级要等下一次探测或使用才会更新。刚升级的账号因为旧等级不够而不会被选来请求新等级才能用的模型，所以要先探测一次（WebUI“探测登录状态”或 `ais2api accounts probe ID`）。
- 账号列表的 `benefit_tier` 为空表示尚未确认；账号被使用或探测一次后即可显示。
- Plus 账号显示为 Plus，但社区已确认它的额度与 Free 相同，额度表用 `tier_fallback` 把 `plus` 映射到 `free`。

## 调度规则

每个请求使用解析别名、去掉思考后缀和 `-search` 之后的模型 id（不区分大小写）查询额度表：

- 模型不在表中（例如图片模型）：不过滤、不估算。
- 账号等级未知：不过滤、不估算，排序时排在已知等级之后。
- 该等级的条目为 `null`：该等级不能使用这个模型，选号时跳过。
- 该等级的条目为 `{requests, tokens}`：可以使用，每日上限为请求次数和 Token 数，任一项用完即当日用完。
- 条目中没有该等级时，先按 `tier_fallback` 查找，仍然没有则视为可用且没有已知上限。

选号时的顺序：

1. 排除等级已知、但不能使用该模型的账号。
2. 今日额度未用完的账号排在已用完的前面。
3. 当前账号（浏览器中驻留的会话）。
4. 首选账号。
5. 等级从低到高：Free、Plus、Pro、Ultra，未知等级最后。这样高等级账号的额度会留给只有它们能用的模型。
6. 最近成功使用该模型的账号。
7. 导入顺序。

所有可用账号的等级都已知且都不能使用该模型时，请求直接返回 403 `tier_insufficient`，不会尝试任何账号。生成时收到 403、并且页面刚确认的等级不能使用该模型时，只把该账号排除在本次请求之外，然后换下一个账号：不重建会话、不冷却，也不切换浏览器后端。

## 今日用量估算

- **计数**：每一轮产生了内容的上游调用记 1 次请求，Token 取该轮自己的 `totalTokenCount`。续写的每一轮分别计数；没有产生内容就失败的尝试不计。
- **日界**：太平洋时间零点，即北京时间冬令时 16:00、夏令时 15:00，已处理夏令时切换。
- **范围**：只统计经本服务发出的请求；在网页或其他工具中使用同一账号不会计入。
- **保留**：按账号、模型和日期保存，保留 7 天。重置账号（WebUI 中的“重置失败与禁用状态”或 `POST /accounts/{id}/reset`）会清空该账号的用量；清除冷却不会，因为上游额度仍然是用完的状态。
- **每日额度 429**：上游报告当日额度用完时，该模型当日标记为已用完。如果本地估算也已用完，冷却一直持续到下一次重置；否则仍按 60/60/300/300/600 秒逐级冷却（见 [失败重试与冷却](browser.md#失败重试与冷却)），以免估算偏差让账号停用一整天。

## 数据文件

额度表是仓库 `main` 分支的 [`quotas/aistudio.json`](../quotas/aistudio.json)：

```json
{
  "schema_version": 1,
  "published_at": "2026-11-23T00:00:00Z",
  "note": "说明文字（可选）",
  "tier_fallback": { "plus": "free" },
  "models": {
    "gemini-4-argon": {
      "free": null,
      "pro": { "requests": 50, "tokens": 15000000 },
      "ultra": { "requests": 150, "tokens": 20000000 }
    }
  }
}
```

校验规则（不满足时整份文件被拒绝，继续使用已有数据）：

- `schema_version` 必须是 1，否则报 `quota_schema_unsupported`；其他错误报 `invalid_quota_catalog`。
- `published_at` 格式为 `YYYY-MM-DDTHH:MM:SSZ`（UTC）。
- 模型 id 只能使用小写字母、数字、`.`、`_` 和 `-`，最长 256 个字符；`models` 不能为空。
- 等级键只能是 `free`、`plus`、`pro`、`ultra`；值为 `null`，或只含 `requests`（1–1,000,000）和 `tokens`（1–10^12）两个整数的对象。
- `tier_fallback` 只能在已知等级之间映射，且不能链式映射。
- 文件不超过 1 MiB。

| 模型 | Free / Plus | Pro | Ultra |
|---|---|---|---|

| `gemini-4-hydrogen` | 50 次 / 1000 万 | 100 次 / 2500 万 | 150 次 / 3500 万 |
| `gemini-3.1-pro-preview` | 不可用 | 50 次 / 1300 万 | 100 次 / 1600 万 |
| `gemini-3.8-flash` | 50 次 / 500 万 | 100 次 / 2500 万 | 150 次 / 3000 万 |
| `gemini-3.6-flash` | 50 次 / 500 万 | 100 次 / 2500 万 | 150 次 / 3000 万 |

### 更新流程

1. 在 `main` 分支修改 `quotas/aistudio.json`，并把 `published_at` 改为当前 UTC 时间。发布时间较旧的数据永远不会覆盖较新的数据（相同时间可以覆盖）。
2. 合并后，raw 地址约 5 分钟内生效（GitHub 缓存）。
3. 运行中的程序最多 6 小时后自动拉取；失败后至少 1 小时再试，期间继续使用已保存的数据或内置快照。也可以在 WebUI“账号”页的“每日额度”中点击“检查额度数据更新”，或调用 `POST /quotas/refresh` 立即检查。
4. 下一次构建会把新文件内置为快照，单元测试会校验它能否通过解析。

下载地址为 `https://raw.githubusercontent.com/mananekoha114/ais2api/main/quotas/aistudio.json`，使用配置的代理，不发送请求正文或凭据。

## 本地覆盖

配置项 `tier_quotas` 的格式与数据文件的 `models` 相同，按模型整条替换额度表中的条目，或补充表中没有的模型，修改后立即生效。例如让免费号也能使用某个模型：

```json
{
  "tier_quotas": {
    "gemini-4-argon": {
      "free": { "requests": 20, "tokens": 5000000 },
      "pro": { "requests": 50, "tokens": 15000000 },
      "ultra": { "requests": 150, "tokens": 20000000 }
    }
  }
}
```

也可以用环境变量 `AIS2API_TIER_QUOTAS`（JSON）设置，见 [配置参考](configuration.md)。

## 查看

- **WebUI**：“账号”页每个账号显示等级徽章，额度用完时显示“N 个模型额度用完”；展开详情可以看到“今日额度”表格（次数和 Token 的已用量与上限）。页面上方的“每日额度”卡片显示下次重置时间、数据版本和来源。
- **管理 API**：`GET /quotas` 返回数据来源状态和合并后的生效表；账号列表中每个账号带 `benefit_tier` 和 `daily_usage`，顶层带 `quota_resets_at`，见 [管理 API](management-api.md)。
